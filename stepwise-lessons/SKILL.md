# stepwise-lessons：给初学者写循序渐进的课程

## 这套做法从哪来

它是和一位深度学习初学者反复磨合出来的。几条结论决定了下面所有规则：

- **能想象出画面，才算懂。**解释余弦相似度时，"看模式、不看总量"没讲懂；换成"两根箭头的夹角"立刻就懂了。所以每课都要有一个具体的比喻，并且最好配图。
- **概念一多就跟不上。**一课塞进神经元、ReLU、层、矩阵、PCA 对比五个概念，读者就跟不上了；拆成两课以后才顺。
- **比喻混用会打架。**一课里同时出现"折尺""评委""眼镜"三个比喻，读者要在三个画面之间来回切换。一课只用一个比喻。
- **固定标签像套话。**写成"画面：……手算：……公式：……"的模板，读着像流水线产品。讲法顺序只是写作时的思路，不要写成标签。
- **对话框不适合放图。**字符画在对话里会错位，也没法放真图。所以每课写成一个文件，示意图也用 Python 画，不用字符画。
- **讲得好不好，主要看文字。**两次写同一课，结构、比喻都一样，读者却觉得一篇好懂、一篇看不下去。差别在比喻段写得是否和机制一一对应、例子的数字是否干净、正文里数字是否太多。另一次对比里，胜出的一篇整课只用一组取自论文场景的例子，比喻贴合输出的用途，并且把新概念接回了读者熟悉的 K-means。
- **旧比喻别带进新课，开头的问题要在正文里解决。**同一课的两个版本用了同一组核心例子，读者仍觉得一篇明显更好。差的那篇把前两课的"签箱""讨论会"写进了新的认人游戏，读者要同时想三个画面；还先后换了四组数据，开头提出的"两个视图互相抵消"留到练习里才解决。好的那篇只有"照片""画像"两个角色，开头的反例就是正文手算的那张照片，再用一条曲线把它一路转回最低点，问题在同一个例子里提出，也在同一个例子里解决。
- **3D 图比俯视图好懂。**二元函数画成热力图俯视图加剖面图，读者看不懂；换成斜视角的 3D 曲面，加上地面和重点线条，一看就懂。

## 流程

### 1. 弄清四件事

开讲前要知道：

1. **主题**：讲什么。
2. **目标**：学完要能做什么，比如"看懂某篇论文/某段视频"。目标决定讲什么、不讲什么。
3. **起点**：读者懂什么、不懂什么。已经懂的东西正好拿来打比方。
4. **存放目录**：默认放在学习材料旁边的 `lessons/` 子目录。

对话里已有答案的就不要再问。真正缺的，一次问完。

### 2. 有学习材料就先吃透材料

论文、视频、代码仓库这类材料，先整理成笔记写到磁盘上，例如 `study/notes.md`，之后所有讲解都以笔记为准。

- PDF 中的图、公式和算法框：用 `pdftoppm` 渲染对应页后亲自看，不能跳过。
- 视频：用 ffmpeg 抽出音频，再用 funasr 转写成带时间戳的文字稿；按画面变化截图；按章节列出大纲。转写里的同音错字，对照论文更正后记进笔记。
- 这类大批量的提取工作可以交给 subagent，但要让它把结果写到磁盘上。

### 3. 先写课程大纲和第一课

写 `00_课程大纲.md`，内容包括：

- 学习目标，一句话。
- 课程表：课号、内容、对应材料中的位置（论文第几节、视频哪个时间段）。按依赖关系排序，前一课是后一课的基础。
- 每课最多引入 2 个新概念，超出就拆成两课。
- 每课预先选定一个比喻，并且只用这一个。

接着按第 4 节写出第一课，然后停下，请用户确认或调整。大纲有调整时，如果影响到第一课，就重写第一课。

### 4. 一课一课地写，每课写完就停

每课写完后，在对话里简短说明：写了哪个文件、讲了什么、用了什么比喻、有哪些地方自己不太确定。然后停下等用户反馈。

用户说哪里没懂时：

- 换一个比喻或角度重写那一段，不要把原话换个说法再说一遍。
- 修改要直接改文件，图在作图脚本里改了再重新生成。
- 用户对讲法提出的偏好要一直沿用到后面的课。如果有记忆功能，也记下来。

讲课正文由你亲自写，不要交给 subagent。这类内容对质量很敏感，曾经有一份由 subagent 生成的讲义被用户判定为"不适合初学者"。

## 每课怎么写

### 内在顺序

下面是写作时的思路，**不要写成小标题或固定标签**：

1. **开头**：接上一课，用一两句话引出这一课要解决的问题。
2. **为什么需要**：先展示不用这个概念会卡在哪里，最好有具体数字，例如"直线最好也只能把损失降到 2.8"。
3. **比喻**：用一句话给出画面，并配一张图。这个比喻贯穿全课。
4. **小数字例子**：用 2～5 个样本、1～2 维、整数或一位小数，一步一步手算，用表格列出过程。
5. **公式放在最后**：给出一般形式，并用一张"符号 | 含义 | 例子里的值"表把每个符号对回例子。
6. **联系目标材料**：论文第几个公式、视频第几分钟、和读者熟悉的哪个方法对应。
7. **小结**：一段话，用比喻的语言把整课说一遍。
8. **练习**：2～3 道题，答案放在 `<details>` 里。
9. **结尾**：一句话说明下一课为什么需要。

### 写法

- 小标题写这一节讲什么，例如"两把折尺拼成 V 形"。不要用"画面""手算""公式"这类标签。
- 每个术语第一次出现时都要解释，包括看起来很基础的词，比如向量、矩阵、期望、梯度。
- 容易混淆的概念用对比表摆在一起。
- 尽量联系读者已经懂的东西，比如"PCA 就是一层没有 ReLU 的网络"。
- 宁可多写一步，也不要跳步；但和学习目标无关的细节不写。
- 段落之间要自然过渡，像一本好教材。不要写成清单，也不要加多余的强调。
- 不要用破折号插入语、"不是 X 而是 Y"、冒号后揭晓答案这类花哨句式。
- 不要预告"整课只用一个比喻""下面先……再……"，直接讲。
- 优化器名称、学习率、章节号、图号这类细节，只在它们对学习目标有用时才写。每多一个顺带的新名词，都会打断读者的思路。

### 比喻要和机制一一对应

比喻是整课的骨架，引入比喻的那一段最要紧。同一个电报比喻，下面两种写法读起来差别很大：

> **好**：想象一个发报员和一个收报员。发报员拿到一份原文，必须把它压成一封很短的电报发出去；收报员只看得到电报，要凭它把原文写回来。写完以后，两人把还原稿和原文对一对，差得越少，说明电报里留住的信息越多。

> **差**：设想你要把一封信的内容告诉远方的朋友，但只能发电报，而且按字收费，最多发很少几个字。你得先想清楚信里什么最要紧，压缩成几个字发出去；朋友收到后，再凭这几个字把整封信写回来。

差的那段有四个问题：

- **多了机制里没有的东西**。"远方""按字收费"都是多余的。"收费"还暗示多花钱就能多发，可瓶颈是硬上限。
- **少了机制里有的东西**。没有"对稿子"这一步，而这一步就是损失，是整课的核心。
- **角色名前后不一致**。这一段里叫"你""朋友"，紧接着的表格里又叫"发报员""收报员"，读者要重新对应一遍。
- **把模型写成会思考的人**。"你得先想清楚什么最要紧"，暗示编码器事先知道什么重要，可它其实是练出来的。

写比喻段之前，先列出机制的组成部分（输入、处理步骤、中间结果、输出、怎么判断好坏、有什么限制），然后逐项检查：

1. 每个部分在比喻里都有对应，不多也不少；
2. 按数据流动的顺序写，一句话讲一个部分；
3. 角色名定下来以后，全课一字不改地沿用，表格和后文也一样；
4. 判断好坏的那一步（即损失）必须出现在比喻里；
5. 不给角色加上模型没有的能力，比如"想清楚""判断"；
6. 训练改的是哪些东西要说对。两样东西都由网络算出时，不能写成"能改的只有其中一样"；
7. 角色名彼此要好区分，不要只差一个字。"角度照/合成照"容易看混，"照片/画像"不会；
8. 前几课的比喻词不带进来。用到旧工具时叫它的中性名字（softmax、翻倍规则、关系矩阵 $G$），不说"签箱""讨论会"。

### 例子怎么选

- **整课只用一组例子**：反例、主计算、变体、公式对照表都用同一组数据，只有它演示不了时才换。换例子和换比喻一样，读者要重新建立画面。要演示新情况时，往原来那组里加一个样本，不要另起一组。
- **反例就是主例子的开头**：开头用来说明"为什么需要"的那个坏情况，正文要用同一个例子手算出来，并在正文里演示它怎样被解决，例如画一条损失随参数变化的曲线，从坏情况一路下到最低点。不要把解决过程留给练习。
- **例子的对象取自目标材料**：讲 softmax 时用"候选 K = 2、3、4、5 的得分"，而不是抽象的甲、乙、丙。读者一边学概念，一边已经在看论文里的场景。
- **比喻贴着输出的用途选**：softmax 的输出在论文里拿去抽 K，"抽签"就比"分奖金"贴切，因为"中签机会"本身就是概率，后面讲按概率抽样时比喻可以直接沿用。
- **性质要用数字演示，不要只断言**：说"得分变一点，概率也只变一点"，就把得分从 1 改成 1.1，算出概率从 0.5 变成 0.517。
- **每课至少一处接回读者已懂的方法**，例如"K-means 就是温度降到 0 的软分配""PCA 就是没有激活函数的自编码器"。

### 数字要干净、要少

- **第一个例子要干净**：挑合适的数据，让第一次手算的结果是整数，或者正好是 0。不完美的情况放到后面，单独用一个样本演示，例如先让三个点正好在直线上，再加一个偏离直线的点。
- **反面例子要极端**：要一眼就能看出它为什么不好，例如三封电报全是 0，收报员分不出谁是谁。不要用需要额外推理才能看懂的反例。
- **正文只留讲道理必需的数字**：训练过程只报起点、终点和用来对比的那个数；中间步骤的小数（4.5625、0.047 之类）不写。读者会想逐个核对，数字一多就看不下去。

### 数字必须正确

文中每个数字都要用 Python 实际算过。如果四舍五入后和正文写的不一致（比如 b = 0.99 写成了 1.00），以实际计算结果为准。

材料里没写的机制，不要编一组数字把它讲成定论。比如论文没说视图权重怎么学，就不要编两个视图的损失值来"演示"它是怎么学出来的。确实需要推测时，放到联系目标材料的那一节，并写明是推测。

## 插图

### 原则

- 插图用 matplotlib 画成 PNG，放在课程目录的 `img/` 下，文件名形如 `l03_relu.png`。
- 全部插图由课程目录里的一个 `make_figures.py` 生成，改图就改这个脚本，然后重新运行。
- 先把本技能的 `scripts/lessonfig.py` 复制到课程目录，再在 `make_figures.py` 里 `from lessonfig import *`。这样课程目录不依赖技能目录，换台机器也能运行。
- **每张图生成后都要用 Read 工具亲自看一遍**，确认没有重叠、遮挡、文字被截断，再写进正文。

### 选图

| 要展示的东西 | 画法 |
|---|---|
| 一元函数、几个函数相加 | 折线图；相加的过程画成"A + B = C"三联图（`sum_panels`） |
| 二元函数（曲面、决策边界、损失地形） | **3D 曲面**（`surface3d`）：斜视角，加半透明地面 z=0，关键线条（折痕、剖面线）加粗并置于最上层。不要画热力图俯视图或剖面图，除非用户要求 |
| 样本、聚类 | 散点图，按簇着色，必要时标出样本名 |
| 向量、方向 | 从原点出发的箭头；需要强调的箭头单独放一个子图 |
| 训练过程 | 左图画模型逐步拟合数据，右图画损失曲线 |
| 网络结构、流程、比喻里的角色关系 | 用 matplotlib 画方框和箭头（`flow_diagram`），框里可以写中文。能用 Python 画的就不要用字符画；字符画只在实在画不出来时才用，而且只放英文、数字和符号 |

### 作图的坑

`lessonfig.py` 已经处理了下面这些问题，自己写作图代码时也要注意：

- 中文字体用 Microsoft YaHei，并设置 `axes.unicode_minus=False`。
- 雅黑没有 ₁、₂ 这类下标字形，下标要用 mathtext 写成 `$x_1$`。
- 3D 图中的线条会被曲面遮住，要设置 `ax.computed_zorder = False`，并给线条更高的 zorder。
- 3D 图的视角要多试几个：先用小图并排渲染几个候选视角，选中后再出正式图。
- 同一张图里两个点重合时，在正文里说明，例如"两个 B 叠在了一起"。

## 文件格式

- 每课一个 Markdown 文件，命名为 `NN_标题.md`，例如 `03_一个神经元.md`。
- 用户常用 VS Code 的 Markdown Preview Enhanced 预览，所以：
  - 公式用 `$...$` 和 `$$...$$`；
  - 折叠答案用 `<details><summary>答案</summary> … </details>`，`<summary>` 后面要空一行；
  - 图片用相对路径 `![说明](img/xxx.png)`。
- 用户没要求时，不要另外生成 HTML 讲义或网页。
- 用用户的语言写。用户用中文就写简体中文。
